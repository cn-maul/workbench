# 工作台软件开发计划书

---

## 一、项目概述

### 1.1 项目名称

**工作台（Workbench）**

### 1.2 项目定位

一个单机、单 exe、工作目录优先的个人工作台。日常零散东西自动进月度项目，大工作手动建项目，项目里只有记录库和文件库。

### 1.3 核心原则

1. **文件系统优先** —— 文件是真相，数据库是缓存。
2. **单 exe 优先** —— 前端 embed，双击运行。
3. **最少模块** —— 不引入不必要的框架和依赖。
4. **最少概念** —— 项目、记录、文件、设置，四个词讲完。
5. **可恢复** —— 索引可重建，备份即拷贝文件夹。
6. **可读** —— 文件在硬盘上直接用，不加密、不打包、不改格式。
7. **不做** —— 凡是能不做的，都不做。

### 1.4 目标用户

个人使用，单机运行，Windows 优先。

## 二、功能规格

### 2.1 项目

| 类型 | 创建方式 | 用途 |
|---|---|---|
| 月度项目 | 自动 | 收纳零散记录和零散文件 |
| 自定义项目 | 手动 | 大工作、需要长期保留的工作 |

- 月度项目按 `年/月` 组织，命名如 `2026-09`。
- **月度项目延迟落盘**：当月没写入任何内容前，磁盘上不存在该目录。左侧树里的"当前月度"是虚拟节点，第一次新建记录/上传时才真正建目录。
- 自定义项目命名自由，如 `2026年安全检查`。
- 项目里只有两个 Tab：记录库、文件库。
- 项目没有状态、没有负责人、没有截止日期、没有优先级。

### 2.2 记录库

- 只存 `.md` 文件。
- 上传 `.md` → 存进项目 `records/`。
- 新建记录 → 输入标题，生成空白 `.md`（命名规则见 5.4），直接在页面里编辑。
- 记录支持页面内**格式化查看与编辑**：前端读取 md 原文，渲染显示语法格式，编辑后保存回磁盘原文件。
- 文件库的非 md 文件（pdf/word 等）不做预览，只支持下载。
- 记录里可以引用文件库的文件，写法：`[[原始文件名]]`。
- 后端扫描 md 文本，把 `[[...]]` 解析成文件库里的下载链接。
- **引用的是"名字"，不是某份文件**：同名文件删除后重传，引用自动指向新文件；文件不存在时引用标灰提示。

### 2.3 文件库

- 允许类型白名单：
  - 图片：`jpg`、`jpeg`、`png`
  - Word：`doc`、`docx`
  - PPT：`ppt`、`pptx`
  - Excel：`xls`、`xlsx`
  - PDF：`pdf`
  - 压缩包：`zip`、`rar`、`7z`
- 只支持上传和下载，不支持预览。
- 上传后统一重命名，避免重名。
- 列表显示原始文件名、类型、大小、上传时间、下载按钮。

### 2.4 快捷入口

- **快速记录**：不选项目，直接进当前月度项目。
- **快速上传**：不选项目，直接进当前月度项目文件库。
- 如果先进入某个自定义项目，再点添加，就进那个项目。

### 2.5 设置（工作目录）

Obsidian 库模式，只有一项核心设置——**工作目录**：

- 所有项目、`index.db`、设置都在用户指定的工作目录里，exe 不放数据。
- exe 同目录 `workbench.json` 只记一个指针：当前工作目录路径。这是全程序唯一不可重建的文件。
- 首次启动、或指针指向的目录不存在时，页面引导用户选择/新建工作目录。
- 换机/搬家：拷走工作目录 → 新机器双击 exe → 指定该目录 → 全量还原。

### 2.6 明确不做

- 不做登录、权限、用户
- 不做状态、流程、审批
- 不做周期规则、提醒、日历
- 不做文件库文档的在线预览（md 记录的格式化查看/编辑除外）
- 不做搜索（第一版）
- 不做标签、分类、收藏
- 不做统计、报表
- 不做多人、局域网、云同步
- 不做删除项目（第一版）
- 不做批量下载（第一版）

## 三、技术栈

### 3.1 后端

**版本基线：Go 1.27（最低要求），所有依赖取当前最新稳定版，并记录在 `go.mod` / `package.json` 中。**

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | Go 1.27+ | 单二进制、跨平台、标准库强；用 iter、range over func、新方法路由等现成特性 |
| JSON | `encoding/json/v2`（Go 1.27 起为稳定标准库，直接 import，无需 GOEXPERIMENT） | v2 API：`json.MarshalStringer`、`DetectStringifyOptions` 等 |
| Web 框架 | Gin（最新稳定版） | 轻量、成熟、路由清晰；与 net/http 新方法路由冲突时，可直接回归标准库，接口层不变 |
| 数据库 | SQLite | 单文件、零配置 |
| SQLite 驱动 | `modernc.org/sqlite`（跟随其最新发行） | 纯 Go，无 CGO，好交叉编译 |
| 数据访问 | `database/sql` + 手写 SQL | 表少，不引 ORM |
| 前端嵌入 | `embed.FS` | 官方标准，单 exe |
| 打包 | `go build` | 一条命令 |
| 日志 | `log/slog` | 官方结构化日志，替代老 `log` |

**第三方依赖上限三个：Gin、modernc.org/sqlite、（备用）json-iterator。其余全用标准库。**

**不引入：** GORM、Redis、消息队列、定时任务、配置中心、DI 框架、swaggo 之类的文档生成器。

### 3.2 前端

| 项 | 选型 |
|---|---|
| 框架 | Vue 3（最新稳定 minor） |
| 构建 | Vite（最新稳定版） |
| 语言 | TypeScript |
| UI | **不用组件库**——自写极简样式，**视觉基准参照 HeroUI**（抄设计 tokens：配色、圆角、阴影、字体层级），不引入 React/Tailwind 体系 |
| 路由 | Vue Router（仅 3 个页面） |
| 状态 | 不用 Pinia，`ref` / `reactive` + 一个共享 store 模块足够 |
| 请求 | 原生 `fetch`，不引 Axios |
| Markdown 渲染 | `markdown-it` + `DOMPurify`（渲染语法格式，净化 HTML 防 XSS） |

前端运行时第三方依赖合计四个：vue、vue-router、markdown-it、dompurify（Vite/TS 为构建期）。样式手写，不引 Tailwind。

**前端性能硬要求**（目标是本地 HTTP 下全程体感零延迟）：

| 项 | 要求 |
|---|---|
| 首屏体积 | JS gzip 后 < 150 KB；`markdown-it` 单独懒加载 chunk，只在打开记录浮层时才拉 |
| 交互指标 | 点项目树 → 列表渲染、点查看 → 渲染完成，本地均 < 50 ms |
| 构建 | Vite 默认 minify + tree-shaking；`target: esnext`，不装 polyfill（浏览器只支持 Chrome/Edge 现代版） |
| md 渲染 | 预览结果按内容哈希缓存，内容未变切页不重渲；DOMPurify 一次性清洗整棵容器，不逐节点过滤 |
| 长列表 | 单项目 > 500 条才上虚拟滚动（自写或 `vue-virtual-scroller`，默认不引依赖） |
| 编辑 | 输入零处理，保存为手动动作，不做实时写盘 |
| 上传下载 | 下载走流式响应不整读进内存；上传 > 20 MB 时 fetch ReadableStream 分块并显示进度 |

### 3.3 运行形态

```text
开发时（仅写代码阶段，交付后不存在）：
  前端 Vite dev server  →  代理 /api  →  Go 后端   ← 为了热更新，临时跑两个进程

生产时（用户实际使用，唯一形态）：
  Vue build → dist → embed 进 Go → 单个 exe
  双击 → 一个 Go 进程同时提供前端静态文件和 API → 自动开浏览器
  访问 127.0.0.1:8080（8080 被占时自动 +1，见 8.5）
```

前端资源打进 exe，**启动=双击一次**，没有独立的前端服务、没有 Node 运行时。

### 3.4 部署形态

- Windows 优先。
- 双击 exe → 单进程启动（前端+API 同一个 Go 进程）→ 自动开浏览器。
- 不需要安装 Node、Go、数据库、Web 服务器。

## 四、架构设计

### 4.1 总体架构

```text
浏览器 / Vue3 前端
        │ HTTP JSON + 文件上传下载
        ▼
Go 后端 API 服务
        │
        ├─ SQLite 数据库：查询缓存，可删可重建
        ├─ 本地存储目录：真实 md 文件、Word/PDF/图片等
        └─ assets.json 清单：原始文件名的权威记录（真相）
```

### 4.2 后端模块

| 模块 | 职责 |
|---|---|
| 配置 | 读写工作目录指针（exe 同目录 `workbench.json`），首启/目录缺失时引导 |
| 项目 | 创建、列出、获取月度/自定义项目 |
| 记录 | 上传 md、新建空白 md、读取 md 文本、原子写回 md 文本 |
| 文件 | 上传白名单文件、下载、列列表 |
| 存储 | 重命名、原子写入、目录组织、维护 assets.json 清单、临时文件清理 |
| 索引 | SQLite 读写，启动时以 assets.json 清单为准对账重建 |
| 引用 | 扫描 md 里的 `[[文件名]]`，匹配文件库 |
| 静态服务 | embed 前端，SPA 回退到 index.html |
| 启动 | 初始化、探测工作目录、探测/绑定端口（在跑则开浏览器退出）、开浏览器 |

### 4.3 前端模块

| 模块 | 职责 |
|---|---|
| 项目树 | 左侧，展示当前月度、自定义、历史月度 |
| 记录库 | 记录列表、上传、新建、下载、查看引用 |
| 记录编辑 | md 渲染查看、页面内编辑、保存回写、编辑态下的 `[[...]]` 链接 |
| 文件库 | 文件列表、上传、下载 |
| 设置页 | 查看当前工作目录、重新指定工作目录 |
| 请求层 | 统一封装 API 调用 |
| 路由 | 项目详情、设置 |

### 4.4 模块间关系

```text
前端
 ├─ 项目树 ──→ 项目 API
 ├─ 记录库 ──→ 记录 API ──→ 存储模块 ──→ 文件系统
 ├─ 文件库 ──→ 文件 API ──→ 存储模块 ──→ 文件系统
 └─ 设置页 ──→ 设置 API ──→ 配置模块

后端
 ├─ 索引模块 ──→ assets.json 清单（真相）+ SQLite（派生缓存）
 ├─ 引用模块 ──→ 读 md + 查索引
 └─ 启动模块 ──→ 初始化一切
```

## 五、数据设计

### 5.1 核心原则

> **文件系统是真相，SQLite 只是查询缓存。**
>
> 原始文件名的权威记录在每个项目的 `assets.json` 清单里；SQLite 里的元数据只是派生缓存。启动时以清单为准，与磁盘实际文件对账后重建库。删库不丢数据。

### 5.2 目录结构

```text
工作台.exe
workbench.json             # 只存工作目录指针 {"workspace": "D:\\我的工作台"}

D:\我的工作台\              # 工作目录（用户指定，备份=拷这个文件夹）
├─ index.db                # SQLite，可删可重建
├─ monthly/
│   └─ 2026/
│       └─ 2026-09/
│           ├─ assets.json   # 本项目资产清单（真相）
│           ├─ records/    # .md
│           └─ files/      # 白名单文件
└─ custom/
    └─ 1_2026年安全检查/
        ├─ assets.json
        ├─ records/
        └─ files/
```

### 5.3 数据库表

**projects**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| name | TEXT | 项目名 |
| type | TEXT | monthly / custom |
| year_month | TEXT | 月度项目用，如 2026-09 |
| created_at | TEXT | 创建时间 |

**assets**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| project_id | INTEGER | 所属项目 |
| category | TEXT | record / file |
| original_name | TEXT | 原始文件名 |
| stored_name | TEXT | 重命名后的文件名 |
| stored_path | TEXT | 相对工作目录的路径 |
| ext | TEXT | 扩展名 |
| size | INTEGER | 文件大小 |
| uploaded_at | TEXT | 上传时间 |

**settings**

| 字段 | 类型 | 说明 |
|---|---|---|
| key | TEXT | 主键 |
| value | TEXT | 值 |

settings 当前只有一条：`workspace` = 当前工作目录路径（自省用）。权威指针是 exe 同目录 `workbench.json`，删库重建后从指针写回。

### 5.4 重命名规则

```text
YYYYMMDD_原文件名.扩展名
```

冲突时追加 `_2`、`_3`：

```text
20260926_安全检查表.pdf
20260926_安全检查表_2.pdf
```

新建空白记录同样走这条规则：

- 用户在浮层/列表输入标题（如"周小结"）→ 原始名 = `周小结.md`（前端显示、下载还原均用它），存储名 = `20260926_周小结.md`。
- 标题清洗：去掉 `\ / : * ? " < > |` 与首尾空白，去掉结尾多余的 `.md`，限长 50 字，超长截断。
- 清洗后为空 → 自动用"未命名记录"，不阻塞创建。

### 5.5 索引重建

启动时（以及每次重新指定工作目录后）：

1. 扫描 `monthly/` 和 `custom/`，重建 `projects` 表
2. 逐项目读 `assets.json`，作为元数据权威来源
3. 对账：清单有、磁盘没 → 删条目；磁盘有、清单没 → 按兜底规则补进清单（`original_name` 匹配 `^\d{8}_` 前缀则剥离，否则等于文件名；`uploaded_at` 用文件 mtime；category 由所在子目录推断）
4. 用对账后的清单重建 `assets` 表
5. 删掉残留 `.tmp_*` 临时文件

不一致时以文件系统和 `assets.json` 为准，SQLite 永远服从对账结果。清单丢失时降级为纯文件系统扫描（全部走兜底规则），软件仍可用，只是手工改过名的文件原始名可能不还原。

### 5.6 assets.json 清单

每个项目目录下一个人可读、可备份的 JSON 清单，只存文件系统推不出来的字段：

```json
{
  "20260926_安全检查表.pdf": {
    "original_name": "安全检查表.pdf",
    "uploaded_at": "2026-09-26T14:32:00+08:00"
  }
}
```

- **key**：存储文件名（5.4 重命名后的名字）。
- **value**：仅 `original_name` 和 `uploaded_at` 两个字段。`category`、`ext`、`size` 由扫描现场推断，清单不存，避免多处真相。
- **写入**：上传/新建记录成功后，整文件临时写 + 原子重命名更新。
- **并发**：单进程单用户，无需加锁。
- **前端不感知**：清单是后端内部机制，不新增任何 API。

## 六、API 设计

统一前缀：`/api/v1`

### 6.1 项目

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/projects` | 项目列表（当前月度 + 自定义 + 历史月度） |
| POST | `/projects` | 新建自定义项目 |
| GET | `/projects/current-monthly` | 当前月度项目，**只读不创建**：已存在返回实体；不存在返回虚拟节点（`pending: true`，无固定 id） |
| GET | `/projects/:id` | 项目详情 |
| GET | `/projects/:id/assets` | 项目下资产列表，`?category=record\|file` |

任何写入（upload / records/blank）前，后端统一 ensure 目标项目目录与库记录——月度项目由此才落盘，虚拟节点换成真实 id。

### 6.2 资产

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/:id/upload` | 上传文件，multipart，字段 `category` + `file` |
| POST | `/projects/:id/records/blank` | 新建空白 md，body：`{ "title": "周小结" }` |
| GET | `/assets/:id/download` | 下载，用原始文件名 |
| GET | `/assets/:id/text` | 读取 md 文本（供前端渲染） |
| PUT | `/assets/:id/text` | 保存 md 文本，原子写回磁盘原文件 |
| GET | `/records/:id/references` | 扫描 `[[文件名]]`，返回匹配结果 |

`text` 读写只作用于 `category=record` 的资产；读写时顺带 `stat` 磁盘文件刷新缓存里的 size/mtime，页面编辑后列表数字不会过期。

### 6.3 设置（工作目录）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/settings` | 返回 `{ workspace, workspace_exists, needs_select }` |
| PUT | `/settings` | 指定/更换工作目录 `{ "workspace": "D:\\我的工作台" }`，立即写指针、建目录、全量重建索引 |

- 指针缺失或指向的目录不存在时，除引导页所需接口外所有 API 返回 428 `workspace_required`，前端跳转引导页。
- 更换工作目录**不迁移数据**：旧目录原样留在硬盘上，界面提示旧路径。

### 6.4 接口原则

- 不用分页（数据量小）
- 不做批量接口
- 不做复杂查询
- 不做版本号管理


- 设置页只有这一项，显示当前路径，只读。
- "重新指定"弹确认框：说明旧数据不会被搬走、切换后立即全量重建索引。
- 首次启动（或工作目录丢失）时，前端跳引导页：选一个文件夹作为工作目录，选定后进主界面。

### 7.6 记录查看 / 编辑（浮层）

```text
┌─ 工作记录.md ───────────────────── [下载] [保存] [×] ─┐
│  [ 预览 ] [ 编辑 ]                                    │
│                                                       │
│  预览态：渲染后的语法格式                              │
│    # 九月安全检查                                     │
│    ## 发现问题                                        │
│    • 3 号楼灭火器过期          ← 标题、列表、加粗渲染  │
│    🔗 检查表.pdf               ← [[...]] 变下载链接    │
│                                                       │
│  编辑态：textarea 原文 + 引用插入下拉（列文件库文件名） │
└───────────────────────────────────────────────────────┘
```

- 默认进预览态；点编辑切 textarea；点保存 `PUT /text` 回写磁盘，成功提示后停留。
- 预览渲染走 `markdown-it` + `DOMPurify`，md 里的 HTML/脚本不执行。
- 新建空白记录后直接浮层打开编辑态。

## 八、可靠性设计

### 8.1 上传原子化

```text
写临时文件 → fsync → 原子重命名 → 更新 assets.json（临时写 + 原子重命名）→ 入库
```

任何一步失败都不产生半截文件。最坏情况是清单与 SQLite 不一致，重启对账自动修复。

### 8.2 索引可重建

- 删掉 `index.db`，重启按 `assets.json` 清单+文件系统自动重建。
- 工作目录指针在 exe 同目录的 `workbench.json` 里，不在库里，删库不影响找目录。
- 文件系统与清单永远是对的，SQLite 只是派生缓存。

### 8.3 备份极简

- 关掉软件，拷走整个工作目录文件夹。
- 恢复就是拷回来，双击 exe，指定那个目录。

### 8.4 无隐性状态

- 不靠内存缓存
- 不靠后台任务
- 不靠定时器
- 重启后一切从文件系统重建

### 8.5 失败处理

| 场景 | 处理 |
|---|---|
| 数据库损坏 | 删掉，按清单+文件系统重建 |
| assets.json 丢失/损坏 | 降级纯文件系统扫描，原始名按兜底规则 |
| 上传中断 | 临时文件残留，启动时清理 |
| 文件名冲突 | 自动追加序号 |
| 项目文件夹被手动改名 | 以文件夹为准，重建索引 |
| 工作目录被移动/换机器 | 指针失效 → 引导页重新指定 → 自动全量重建 |
| 端口被占（自家实例在跑） | 直接开浏览器到旧实例，本进程退出 |
| 端口被占（别的程序） | 自动 +1 换端口，开浏览器到实际端口 |

## 九、开发阶段与任务清单

### 9.1 阶段划分

| 阶段 | 内容 | 产出 |
|---|---|---|
| 第一阶段 | 后端骨架 + 数据库 + 存储 | 可启动的 Go 服务 |
| 第二阶段 | 项目模块 | 项目列表、创建、当前月度 |
| 第三阶段 | 资产模块 | 上传、下载、列表、新建 md |
| 第四阶段 | 引用模块 | 扫描 `[[文件名]]` |
| 第五阶段 | 前端骨架 | 极简 UI + Vue3 + 路由 + 项目树 |
| 第六阶段 | 前端功能 | 记录库、文件库、设置页 |
| 第七阶段 | 嵌入打包 | 单 exe，自动开浏览器 |
| 第八阶段 | 测试与修复 | 完整闭环可用 |

### 9.2 详细任务清单

#### 第一阶段：后端骨架

1. 初始化 Go module，引入 Gin、SQLite 驱动
2. 实现配置模块：读写工作目录指针 `workbench.json`；指针缺失/目录不存在 → `needs_select`
3. 实现引导接口：`PUT /settings` 保存工作目录、写指针
4. 实现 SQLite 初始化：打开工作目录下 `index.db`，建表、建索引
5. 实现目录初始化：工作目录确定后创建 `monthly/`、`custom/`
6. 实现启动流程：探测端口（自家实例已在跑 → 开浏览器退出；否则从 8080 起 +1 找空闲端口绑定）→ 监听
7. 实现临时文件清理：启动时删 `.tmp_*`

#### 第二阶段：项目模块

1. 实现 `GET /projects`：当前月度虚拟节点 + 已存在的历史月度 + 自定义
2. 实现 `POST /projects`：创建自定义项目文件夹 + 入库
3. 实现 `GET /projects/current-monthly`：只读不建，缺失时返回 pending 虚拟节点
4. 实现统一 ensure 写入前置：任何上传/新建记录先保证项目目录与库记录存在（月度项目由此落盘）
5. 实现 `GET /projects/:id`：项目详情
6. 实现索引重建：扫描 `monthly/`、`custom/`，重建 projects 表

#### 第三阶段：资产模块

1. 实现 `GET /projects/:id/assets`：按 category 查列表
2. 实现 `POST /projects/:id/upload`：校验扩展名、临时文件、原子重命名、更新 assets.json 清单、入库
3. 实现 `POST /projects/:id/records/blank`：生成空白 md，同步更新清单
4. 实现 `GET /assets/:id/download`：流式返回，设置原始文件名
5. 实现 `GET /assets/:id/text`：读取 md 文本；实现 `PUT /assets/:id/text`：临时文件 + 原子重命名写回
6. 实现索引重建：以 `assets.json` 为准，与 `records/`、`files/` 实际文件对账，重建 assets 表

#### 第四阶段：引用模块

1. 实现 `GET /records/:id/references`：读 md，正则 `\[\[(.+?)\]\]`
2. 匹配同项目 `category=file` 的 `original_name`，精确匹配；多份同名时默认取最新上传的一份，"查看引用"列出全部同名候选
3. 未命中时剥掉尾部 `_N` 后缀重试一次（兼容误写存储名的引用）
4. 返回匹配结果：名称、asset_id、是否存在（未命中 → 前端标灰）

#### 第五阶段：前端骨架

1. 初始化 Vue3 + Vite + TypeScript（不引 UI 库，依赖仅 vue / vue-router / markdown-it / dompurify）
2. 极简样式底座：自写 CSS，设计 tokens（色板、圆角、阴影、字体）对照 HeroUI 官网观感手工提取；组件样式（按钮、表格、弹层、拖放区）合计不超过约 300 行
3. 配置路由：首启引导、项目详情、设置
4. 配置请求层：原生 `fetch` 薄封装，baseURL `/api/v1`，统一错误提示
5. 配置 Vite 代理：`/api` → `127.0.0.1:8080`
6. 实现左侧项目树组件
7. 实现页面布局：左树右内容
8. 实现自写上传组件：选文件、拖放、进行中状态、错误提示（替代 ElUpload）
9. 实现自写浮层组件：原生 `<dialog>` 或 div + CSS（替代 ElDialog）

#### 第六阶段：前端功能

1. 记录库 Tab：列表、上传、新建、下载、查看引用
2. 记录浮层（用第五阶段的自写浮层组件）：预览/编辑双态，markdown 渲染，保存回写，引用插入下拉
3. 文件库 Tab：列表、上传、下载
4. 上传交互：扩展名校验、上传中、失败提示
5. 新建记录交互：输入标题（前端校验+清洗提示）、生成、直接进浮层编辑态；默认标题"未命名记录 + 日期"
6. 设置页：显示当前工作目录、重新指定（含确认提示）；首启引导页
7. 项目切换：点击项目树刷新右侧

#### 第七阶段：嵌入打包

1. 前端 `npm run build` 产出 dist
2. 复制 dist 到 `internal/web/dist`
3. 实现 `embed.FS` 嵌入
4. 实现 SPA 回退：非 API 路径返回 index.html
5. 实现探测+复用策略：默认端口被占时请求 `GET /api/v1/settings`，是自家 → 开浏览器到旧实例并退出；非自家 → 端口 +1 重试

## 十二、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| SQLite 并发写 | 单机单用户，无并发 | 不需要处理 |
| 大文件上传 | 内存占用 | 流式写入临时文件 |
| Windows 路径分隔符 | 兼容性 | 统一用 `filepath` 包 |
| 中文文件名乱码 | 下载文件名 | 用 RFC 5987 编码 |
| 端口冲突 | 启动失败 | 探测+复用：自家在跑开浏览器退出，他人占则自动换端口 |
| 浏览器兼容 | 页面异常 | 只支持 Chrome/Edge 现代浏览器 |
| 磁盘满 | 上传失败 | 提示错误，不破坏已有文件 |
